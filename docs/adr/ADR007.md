# ADR007: The circuit breaker, shared state, and what a dropped permit means

**Status:** Accepted

## Context

Retry was the first tool. On its own it makes an outage worse: every client that failed retries,
so a service that is already struggling gets more load at the worst possible moment. A breaker is
the other half of that story, and it is the tool that makes "resilience toolkit" more than a name.

It also breaks a pattern. Every other piece of mettle is owned by one call. A breaker is only
useful when everyone calling a dependency shares one, so it needed an ownership model the crate
had not used before.

## Decisions

**1. Shared through `&self`, with the decision logic split out.**
`CircuitBreaker` holds a `Mutex<Machine>` and is used through `&self`, normally from inside an
`Arc`. That is the opposite of `Backoff`, which ADR002 deliberately takes by value with no `Clone`
bound. The difference is the point of the tool: a backoff that one call owns privately is correct,
and a breaker that one call owns privately is useless.

`Machine` holds the state machine with no lock, no clock and no logging. Everything interesting
about a breaker is "what happened, and how long ago", so keeping that pure means the whole
transition table is tested by calling functions with hand-written `Instant`s: no mock, no threads,
no sleeps. The locking wrapper is then small enough to reason about on its own.

One mutex, not atomics or sharding. The critical section is a handful of integer operations, no
user code runs inside it, and the honest fix if it ever contends is per-key breakers rather than a
lock-free rewrite. We would rather have an obviously correct breaker than a clever one.

**2. A new `Now` trait, rather than reusing `Clock`.**
Both existing `Clock` traits pair `now()` with a `sleep()`, and each lives behind a Cargo feature
because their `sleep` differs. A breaker never sleeps, and one breaker type has to compile whether
you enabled `async`, `blocking`, or both. So it takes a smaller trait.

The impls are concrete rather than blanket. `impl<C: clock::Clock> Now for C` together with
`impl<C: blocking::Clock> Now for C` overlaps for any type implementing both, which is E0119, and
every mock clock in this crate's own tests implements both.

`Now` is implemented for `&C` and `Arc<C>` as well as for the two built-in clocks. The breaker
takes its time source by value and keeps it, so without those a caller could hand over a mock and
then have no way to advance it. `Arc<C>` is the shape that matters in practice, since a breaker is
normally shared anyway.

There is no `SystemNow` and no default type parameter on `CircuitBreaker`. A default reading
`Instant::now()` would silently ignore `tokio::time::pause`, so a breaker built inside a
`#[tokio::test(start_paused = true)]` would never leave `Open` no matter how far the test advanced
time. That is the bug the comment in `clock.rs` already exists to prevent, and a default would
reintroduce it one tool over. Making the time source an argument keeps it visible.

**3. Dropping a `Permit` counts as a failure.**
This is the largest semantic call here and the one that cannot be walked back quietly: changing it
later alters everyone's trip behaviour with no compile error to warn them.

A permit that is dropped without reporting means the call was abandoned, panicked, or hung. All
three are evidence against the dependency, and the hang is the one that matters most, because a
dependency that stops answering never produces an error for a breaker to count. Recording nothing
would leave the breaker blind to exactly the outage it is for.

The cost is real: the losing branch of a `select!`, or a hedged request, records a failure it
arguably shouldn't. `Permit::ignore()` is the escape hatch, and it is documented on the method
rather than buried.

**4. A generation token, so a late report cannot corrupt a live period.**
Every transition bumps a counter, and a permit carries the value it was issued under. A report
whose generation no longer matches is discarded entirely. Without it, a slow success from before a
trip can close a breaker that just re-opened.

**5. The window is cleared on every transition.**
A breaker that carries its failures into the recovered state re-opens on the first failure after
recovery, forever. This is worth naming because every per-call assertion still passes without the
clear; only a test that recovers and then fails once catches it.

**6. The half-open budget is cumulative, and the deadline times out a stuck probe rather than a
quiet period.**
`half_open_max_calls` counts admissions for the whole period rather than limiting concurrency.
Handing a slot back when a probe finishes would let a recovering dependency take unbounded traffic
under a steady workload.

The period also needs a deadline, since a probe that leaks or never answers would otherwise wedge
the breaker half-open forever. The subtle part is what the deadline measures. Anchoring it at the
start of the period is wrong: it means every probe must arrive inside one `wait_duration`, so with
`half_open_max_calls > 1` and callers arriving slower than that, the period dies before it can
collect its quota and the breaker never closes, however healthy the dependency is. That is a
livelock, and it sheds traffic forever.

So the deadline applies only while a probe is outstanding. `HalfOpen` tracks `in_flight`, and the
timer starts when a probe is admitted with nothing else in flight. An idle period between slow
callers is quiet, not stuck, and is left alone. `Permit::ignore` releases the in-flight slot while
keeping the budget spent, so an ignored probe does not look like one that hung.

The same deadline binds the answer, not just the next arrival: `on_success` re-opens instead of
closing when a probe takes longer than `wait_duration` to reply. Without that, a very late `Ok`
could close a breaker that `state()` was already reporting as `Open`. Probes carry a flag so only
they pay for the clock read; an ordinary success in the closed state still reads no clock.

**7. Integer percentages and a `u128` bitset.**
`failure_rate_percent` is a `u8`, so the trip boundary is exact and identical on every machine: at
50% of a full window of 100, the 50th failure trips and the 49th does not. A float threshold makes
that boundary a rounding question and lets `0.0001` past a naive range check. The window is one
`u128`, capped at 128 outcomes, so the breaker allocates nothing at all.

**8. Retry does not know about breakers.**
No `.breaker(..)` builder method, no `StopReason::Rejected`, no `Retryable` trait. Composition is
`retry(|| breaker.call_async(op)).when(BreakerError::is_inner)`, with the breaker innermost.

That order is not a preference. With the breaker outside, an operation that fails twice then
succeeds records one success, so the breaker sees a 50%-broken dependency as perfectly healthy and
is blind to the very amplification it exists to suppress. It also means a single half-open probe
holds the period for an entire retry schedule.

The `.when(..)` line is mandatory, and forgetting it produces a full backoff schedule for calls
that never left the process, so it leads the module docs. Adding `.breaker()` later would mean a
new type parameter on `RetryFuture`, which is breaking in both directions, so this is a decision
rather than a deferral.

## Consequences

mettle has two tools that compose, and the breaker is testable in a way no other Rust breaker is:
inject a mock `Now`, advance it, assert the transition, with no sleeping anywhere. That is the
crate's actual differentiator, since `recloser` and others exist and are fine.

We are committed to `Drop` meaning failure, to the `Now` trait being separate from `Clock`, and to
retry staying ignorant of breakers. The first is behavioural and the other two are structural, and
all three are expensive to reverse.
